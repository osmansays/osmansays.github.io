Pseudocode on paper

You already program for a living. The risk here isn't logic: it's writing with a pencil, no compiler, no tests, and a grader who has 30 seconds per answer. This lesson is about making your answer obviously correct.

Pick one style and say so

The invitation says "C++ or Python style". Write "Pseudocode (Python style)" at the top of your answer and stick to it. Python style needs the least handwriting, and indentation shows structure at a glance. Keep indentation deliberate: draw a faint vertical line down each block if your handwriting drifts.

Pseudocode isn't compiled, so for i from 1 to n is fine and clearer than range(1, n + 1). Just make the bounds unambiguous. More conventions: LibreTexts – Pseudocode Examples for Control Structures.

The five-step method

Use it for every programming question. Steps 1–3 take two minutes and save you from rewriting.

  1. Inputs and outputs. Write them as a comment: # input: n numbers # output: average
  2. One example by hand. Input 4, 8, 6 → average 6.
  3. Plan in plain words, 3–6 lines.
  4. Write the pseudocode. Meaningful names (total, not t).
  5. Trace it with your example, then one edge case: empty input, zero, negative, a single item.
Worked example

"Read 5 temperature readings. Print their average and how many were above 25 °C."

# Pseudocode (Python style)
# input: 5 temperatures   output: average, count above 25
total = 0
count_high = 0
for i from 1 to 5:
    t = input("temperature")
    total = total + t
    if t > 25:
        count_high = count_high + 1
average = total / 5
print("Average:", average)
print("Above 25:", count_high)

The same in C++ style:

// Pseudocode (C++ style)
double total = 0;
int countHigh = 0;
for (int i = 1; i <= 5; i++) {
    double t;
    cin >> t;
    total = total + t;
    if (t > 25) {
        countHigh = countHigh + 1;
    }
}
cout << "Average: " << total / 5 << endl;
cout << "Above 25: " << countHigh << endl;

Trace tables

A trace table is one column per variable, one row per step. It's how you test code with no computer, and some questions may ask "what does this print?". Practise these in your head or on paper, then check.

T1 
total = 0
for i from 1 to 5:
    if i % 2 == 1:
        total = total + i
print(total)
Odd i: 1, 3, 5. Total = 9.
T2 
x = 10
count = 0

    x = x // 2

b = a - b

a = 10; b = 10 − 7 = 3; a = 10 − 3 = 7. It swaps the two values without a temp variable.
T4 
n = 5
result = 1
for i from 1 to n:
    result = result * i
print(result)
1·2·3·4·5 = 120. This is factorial. Starting result = 0 would give 0: the identity for multiplication is 1.
T5 · off-by-one

In real Python, how many numbers does for i in range(1, 5): print(i) print?

1, 2, 3, 4. The end is exclusive. This is exactly why "from 1 to n" with stated inclusive bounds reads better on paper.
T6 · find the bug 
largest = 0
for each x in values:
    if x > largest:
        largest = x
print(largest)
For −5, −2, −9 it prints 0, which isn't in the list. Fix: largest = values[0]. Graders love this edge case.

Your turn: write first

Task: Read a positive integer n and print the sum 1 + 2 + … + n. If the input is not positive, print an error message.

# Pseudocode (Python style)
# input: integer n   output: 1 + 2 + ... + n
n = input("Enter a positive integer")
if n <= 0:
    print("Error: n must be positive")
else:
    total = 0
    for i from 1 to n:
        total = total + i
    print("Sum:", total)

Trace with n = 4: 1 + 2 + 3 + 4 = 10. Bonus line a grader would enjoy: # check: equals n*(n+1)/2.
